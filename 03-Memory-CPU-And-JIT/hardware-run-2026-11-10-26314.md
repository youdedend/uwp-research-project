## New bugs found by this run (ranked)

1. **GPU fence wedge mid-game** (1,225 presents, ~2.5–4.8 GiB): completed-fence counter frozen
   41 s while the app kept allocating and heartbeating. This is the same 800–1,300-present stall
   class as the historical DEVICE_LOST runs — now survivable thanks to the watchdog, but the
   game is unplayable past it. Needs a targeted repro (same route, `cache=cold`) with the
   `copy layer mismatch` path instrumented.
2. **Warm-boot `GameSerial` assertion** (`errors-unknown.log.txt:1-2`):
   `GPU [Debug] <Critical> elf_info.h:107 GameSerial: Assertion Failed!` + `STOP: GPU library
   assertion failed`. Runs 3–4 (`cache=warm`) presented 0 frames with fences 3/2 stuck; run 2
   (`cache=cold`) played fine. Correlates with the warm `driver.vkcache`/precompile path
   (`precompile_inflight.txt` 1 in-flight record, `precompile_quarantine_v2.txt` 1 hash).
   Attribution between runs 3/4 unverified.
3. **`D16Unorm 1x1x1 layers N→N+1` copy-layer-mismatch spam** (5×, texture cache frees id=94–98
   at one guest address) — skipped copies on a depth texture re-map; loud, wedge-adjacent.
4. **False "Low storage" dialog at first boot** (`loader-2026_11_10.log.txt:24-25`):
   `UWP STORAGE WARNING: 0 KiB free on Q:` contradicts `:18 UWP swap selection: Q: free=28439 MiB`
   in the same log. Cosmetic but scary-looking to players.
5. **Memory-contract self-test result=63** (run 1, `memory-selftest.txt`): `swap self-test 63`
   — the first-launch self-test failed its swap probe (it paged 48 MiB and stopped); the game
   boots fine on relaunch (by design), but the test's failure mode should be read out once.
